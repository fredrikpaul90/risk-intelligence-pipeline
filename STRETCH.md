# Stretch Roadmap

If given another week to develop the pipeline beyond this slice, I would tackle these tasks:

1. **Automated Section Discovery**: Use LLM to identify the pages in annual reports that contain sections of interest (risk management, material impacts, risks etc). This is an integral component of the pipeline and will allow it to drop hardcoded page slices and enable processing of full, arbitrary annual reports.
2. **LLM-only parsing**: Benchmark skipping Document AI entirely and sending the unparsed PDF directly to an LLM for section discovery and extraction (see [DESIGN.md's Scaling section](DESIGN.md#scaling-latency-cost-and-throughput) for the provenance trade-off this needs to clear first). May be cheaper — the full PDF's ~200k tokens is well within most LLMs' context limits — but only worth adopting if an evaluation confirms recall, groundedness, and page-level provenance stay equivalent. Currently deferred because the implemented pipeline has satisfactory performance.
3. **Containerization, Cloud Run API & Operational Monitoring**: Package the pipeline into a Docker container and expose it via a FastAPI/Uvicorn service deployed to Google Cloud Run (scale-to-zero compute with async job handling and Cloud Monitoring alerts for latency, token usage, and pipeline failures).
4. **CI/CD Regression & Quality Monitoring**: Move the golden-set evaluation into GitHub Actions workflows to run on PRs, and add scheduled LLM-as-a-judge monitoring to sample production extractions for groundedness and faithfulness over time.
5. **LLM-as-a-judge inline retry gate (conditional)**: Promote item 4's offline judge into a synchronous gate in `extract.py` — a second (non-Gemini, still GCP-hosted) model reviews each section's risks and, on rejection, triggers one bounded re-extraction with feedback. Only worth building if item 4's monitoring shows the deterministic checks in `eval/evaluate.py` miss real errors often enough to justify the extra model call, latency, and second-provider integration. A plain bounded retry loop covers the two-node extract/judge cycle, so no orchestration framework (e.g. LangGraph) is needed.
6. **Document AI Layout Benchmark**: Benchmark Document AI Layout against OCR across multiple report structures to evaluate if richer table/layout detection justifies the higher cost.
7. **Vector Search & RAG based Chatbot**: Store risk record embeddings in a vector database to enable semantic search and conversational natural-language querying for analysts.
